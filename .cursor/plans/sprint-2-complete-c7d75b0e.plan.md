# План ревизии и доработки Sprint 2

## Цель

Сделать проект понятным, чистым и соответствующим требованиям ТЗ, с акцентом на понимание каждой части кода.

## Этап 1: Проверка и тестирование (ручное)

### 1.1 Проверить все страницы на корректное отображение

- Запустить `npm run dev`
- Пройти по всем страницам: login, register, main (чаты), profile, editProfile, editPassword
- Проверить адаптивность (если есть)
- Записать найденные баги в отдельный список

### 1.2 Проверить валидацию на всех формах

- **Login** - попробовать валидные/невалидные данные
- **Register** - проверить все поля, особенно совпадение паролей
- **ChatArea** - попробовать отправить пустое сообщение
- **EditProfile** - проверить валидацию полей
- **EditPassword** - проверить совпадение паролей
- Убедиться что ошибки отображаются:
  - На blur (когда теряешь фокус)
  - На submit (при отправке формы)
  - Визуально (красная рамка + текст ошибки)

### 1.3 Проверить console.log при submit

- Открыть DevTools → Console
- Заполнить формы и отправить
- Убедиться что данные выводятся в правильном формате

## Этап 2: Изучение теории

### 2.1 Разобраться с ESLint

- Прочитать что такое линтер и зачем он нужен
- Понять основные правила в `eslint.config.js`
- Запустить `npm run lint` и понять каждое предупреждение
- **Вопрос для себя:** Как бы я настроил ESLint без Cursor?
  - Ответ: `npm install eslint`, `npx eslint --init`, выбрать preset

### 2.2 Разобраться с Stylelint

- Прочитать что такое stylelint и зачем он нужен
- Понять правила в `.stylelintrc.json`
- Запустить `npm run lint:styles`
- **Вопрос для себя:** Как бы я настроил Stylelint без Cursor?
  - Ответ: `npm install stylelint stylelint-config-standard-scss`, создать конфиг

### 2.3 Изучить MVC паттерн из теории

- Прочитать материалы курса про MVC
- Посмотреть примеры из урока
- Понять разницу между Model, View, Controller
- Записать своими словами что делает каждый слой

## Этап 3: Чистка и упрощение кода

### 3.1 Почистить комментарии

- Удалить лишние комментарии-объяснения
- Оставить только важные комментарии (почему, а не что)
- Убрать закомментированный код

### 3.2 Упростить HTTPTransport

- Посмотреть пример из урока "Реализация fetch"
- Сравнить с текущей реализацией
- Если пример проще и понятнее - заменить
- Главное - понимать каждую строку кода

### 3.3 Проверить структуру классов

- Убедиться что каждый класс делает одну вещь
- Проверить что нет дублирования кода
- Упростить сложные методы

### 3.4 Проверить imports/exports

- Убедиться что все импорты используются
- Убрать неиспользуемые зависимости
- Проверить что exports логичные

## Этап 4: Реализация базового MVC

### 4.1 Создать папки для MVC структуры

```
src/
  models/          # Данные и их структура
  services/        # Работа с данными (API, localStorage)
  controllers/     # Связь между моделями и view
```

### 4.2 Создать Model классы (простые)

```typescript

  phone: string;
}

export class User {
  constructor(public data: UserData) {}
  
  validate(): boolean {
    // Простая валидация

```

### 4.3 Создать Service классы (простые)

```typescript

  private http: HTTPTransport;
```


Важные заметки для Junior разработчика

### Принципы хорошего кода:

1. **Понятность > Сложность** - Если не понимаешь свой код через неделю - он плохой
2. **Простота > Навороченность** - Простое решение часто лучше
3. **Читаемость > Краткость** - Лучше 3 понятные строки чем 1 непонятная

### Как учиться без AI:

1. **Документация** - официальные доки ESLint, Stylelint, TypeScript
2. **GitHub примеры** - ищи "typescript eslint config example"
3. **Курсы** - MDN, Learn TypeScript, JavaScript.info
4. **Практика** - пиши код руками, экспериментируй
