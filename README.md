# Vite Messenger

Современный мессенджер, построенный с использованием TypeScript, Vite и компонентного подхода.

## 🚀 Функциональность

### Авторизация и регистрация
- **Страница авторизации** (`/`) с валидацией полей
- **Страница регистрации** (`/sign-up`) с полной валидацией всех полей
- **Автоматический редирект** на страницу чата после успешной регистрации/авторизации
- **Проверка авторизации** при переходе на защищенные маршруты

### Чаты и сообщения
- **Список чатов** с возможностью выбора чата, отображением истории чата и подсчётом непрочитанных сообщений
- **Область переписки** с отправкой и получением сообщений в реальном времени через WebSocket
- **Создание новых чатов** с добавлением пользователей
- **Удаление пользователей из чата**
- **Загрузка старых сообщений** при прокрутке вверх

### Профиль пользователя
- **Просмотр профиля** (`/settings`) с информацией о пользователе
- **Редактирование данных пользователя** (`/edit-profile`) - изменение имени, логина, email, телефона
- **Изменение пароля** (`/profile/password`)
- **Загрузка аватара** пользователя

### Роутинг
- **SPA роутинг** с поддержкой истории браузера (назад/вперед)
- **Защищенные маршруты** с проверкой авторизации
- **Автоматический редирект** неавторизованных пользователей на страницу входа

### Валидация
- **Валидация форм** в реальном времени (blur + submit)
- **Валидация всех полей** согласно требованиям

### Архитектура
- **Компонентный подход** с Block и EventBus 
- **TypeScript** для типобезопасности
- **MVC паттерн** с разделением на Model, View, Controller

## Технологии

- **TypeScript** - типизация
- **Vite** - сборщик и dev-сервер
- **Handlebars** - шаблонизатор
- **SCSS** - стилизация
- **ESLint** - линтинг TypeScript
- **Stylelint** - линтинг стилей
- **XMLHttpRequest** - HTTP запросы (без fetch/axios)
- **WebSocket** - real-time обмен сообщениями
- **History API** - клиентский роутинг

## Тесты

- **Mocha** - тест-раннер для юнит-тестов
- **Chai** - библиотека для проверок (assertions)
- **Sinon.js** - библиотека для моков, стабов и шпионов
- **JSDom** - эмуляция браузерного окружения для тестов
- **Husky** - Git hooks для автоматизации

## 🚀 Установка и запуск

### Требования
- Node.js 22.18.0+
- npm 10.9.3+

### Команды

```bash

# Запуск dev-сервера

npm run build

# Предварительный просмотр сборки

npm run lint:styles:fix

# Запуск юнит-тестов
npm test
```

## 📋 Валидация

Реализована валидация для всех форм:

- **first_name, second_name** - латиница/кириллица, первая заглавная, без пробелов/цифр
- **login** - 3-20 символов, латиница, может содержать цифры, дефис, подчёркивание
- **email** - латиница, @ и точка, буквы перед точкой
- **password** - 8-40 символов, заглавная буква + цифра
- **password_repeat/confirmPassword** - проверка соответствия основному паролю
- **phone** - 10-15 цифр, может начинаться с +
- **message** - не пустое

Валидация работает на событиях `blur` и `submit`.

## 🔌 API интеграция

Проект интегрирован с REST API и WebSocket API:

### REST API
- **Авторизация**: регистрация (`POST /auth/signup`), вход (`POST /auth/signin`), выход (`POST /auth/logout`), проверка авторизации (`GET /auth/user`)
- **Пользователь**: получение данных (`GET /user/profile`), обновление профиля (`PUT /user/profile`), изменение пароля (`PUT /user/password`), загрузка аватара (`PUT /user/profile/avatar`), поиск пользователей (`POST /user/search`)
- **Чаты**: получение списка чатов (`GET /chats`), создание чата (`POST /chats`), добавление пользователя (`PUT /chats/users`), удаление пользователя (`DELETE /chats/users`), получение токена для WebSocket (`POST /chats/token/{id}`)

### WebSocket API
- **Real-time сообщения**: отправка и получение сообщений в реальном времени через `wss://ya-praktikum.tech/ws/chats/{userId}/{chatId}/{token}`
- **Загрузка истории**: получение старых сообщений при прокрутке (`type: 'get old'`)
- **Ping/Pong**: поддержание соединения (ping каждые 30 секунд)

## 🧪 Тестирование

Проект покрыт юнит-тестами для основных модулей:

- **Шаблонизатор** (`registerComponent.spec.ts`) - тестирование регистрации Handlebars компонентов
- **Роутер** (`router.spec.ts`) - тестирование навигации, защищенных маршрутов, редиректов
- **Компонент** (`block.spec.ts`) - тестирование жизненного цикла, props, событий, рендеринга
- **HTTP Transport** (`HTTPTransport.spec.ts`) - тестирование HTTP запросов, обработки ошибок, заголовков

Тесты написаны с использованием:
- **Mocha** - тест-раннер
- **Chai** - библиотека для проверок (assertions)
- **Sinon.js** - библиотека для моков, стабов и шпионов
- **JSDom** - эмуляция браузерного окружения для тестов

#### Использование Sinon.js

Sinon.js используется в тестах для создания стабов (stubs) и моков (mocks):

**Стабы (Stubs)** - используются для подмены методов и функций:
```typescript
// Пример из router.spec.ts
authControllerStub = sinon.stub(AuthController, 'checkAuth');
authControllerStub.resolves(true); // Возвращает успешный промис
authControllerStub.resolves(false); // Возвращает неуспешный промис

// После теста стаб восстанавливается
authControllerStub.restore();
```

**Моки (Mocks)** - используются для эмуляции внешних зависимостей:
- В `HTTPTransport.spec.ts` используется собственный мок XMLHttpRequest 
- В `router.spec.ts` используются стабы для подмены методов авторизации

Sinon помогает изолировать тестируемый код от внешних зависимостей, делая тесты более надежными и предсказуемыми.

### Запуск тестов

```bash
# Запуск всех тестов
npm test

# Запуск конкретного теста
npm test -- src/core/block.spec.ts

# Запуск с подробным выводом
npx mocha --reporter spec
```

**Где увидеть результаты?**

Результаты тестов выводятся в консоль после выполнения команды `npm test`. Вы увидите:

- ✅ **Зеленые галочки** или `✓` - пройденные тесты
- ❌ **Красные крестики** или `✗` - упавшие тесты
- **Статистику**: количество пройденных/упавших тестов, время выполнения
- **Детали ошибок**: если тест упал, будет показана причина и стек ошибки

Пример успешного вывода:
```
  Router
    Конструктор
      ✓ должен создать единственный экземпляр (singleton)
      ✓ должен установить rootQuery
    use
      ✓ должен добавить маршрут в список маршрутов
    ...

  45 passing (2s)
```

Пример с ошибками:
```
  Router
    Конструктор
      ✓ должен создать единственный экземпляр (singleton)
      ✗ должен установить rootQuery
        Error: expected undefined to exist
        at ... (router.spec.ts:55:15)
    ...

  44 passing (2s)
  1 failing
```

Тесты находятся рядом с тестируемыми файлами и имеют суффикс `.spec.ts`.

## 🔧 Разработка

Проект использует современные инструменты разработки:

- **ESLint** с правилами TypeScript
- **Stylelint** для SCSS
- **EditorConfig** для единообразия кода
